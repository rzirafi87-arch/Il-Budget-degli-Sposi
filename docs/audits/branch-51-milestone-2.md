# Branch 51 — Milestone 2 checkpoint

## Scope

Milestone 2 hardens authentication, event ownership and IDOR boundaries without changing Production data, schema or grants. The 140-route inventory remains authoritative and is regenerated by `scripts/audit-branch51-routes.mjs`.

## Canonical helpers

- `requireSession`: stable `401 AUTHENTICATION_REQUIRED`.
- `requireEventAccess`: authoritative current/explicit event resolution, owner-only or owner/partner contract, `404` for an explicit missing/foreign event, and `409` when a current-event selection is genuinely required.
- `requireEventResource`: resource lookup constrained by both resource ID and authoritative event ID.
- `parseUuid`: rejects malformed identifiers before database access.
- `apiSecurityErrorResponse`: stable sanitized public failures.

## Verified principal and tampering matrix

| Case | Collaborative routes | Owner-only sharing | Data API/RLS |
|---|---|---|---|
| Owner | allowed | allowed | existing owner policies exercised by rebuild/RLS suites |
| Active partner | allowed | `403 OWNER_REQUIRED` | canonical active-membership policies retained |
| Unrelated authenticated user | `404 EVENT_NOT_FOUND` for explicit/foreign event or no accessible current event | `404 EVENT_NOT_FOUND` | direct cross-event access denied by existing RLS suites |
| Anonymous / invalid JWT | `401`; gift-list demo GET/POST remains non-persistent | `401` | anon has no private-table DML grant |
| Malformed UUID | `400` before resource lookup | `400 INVALID_EVENT_ID` | not sent to Data API |
| Altered event/resource ID | query/update/delete remains constrained by resolved `event_id`; foreign row is `404` | authoritative explicit resolver and canonical `public_id` | event/resource policies remain independent of API guards |
| Altered CurrentEvent cookie | resolver ignores inaccessible cookie and never grants access | explicit requested event is checked independently | cookie is not an RLS input |
| Injected `owner_id` | ignored; update allowlists do not include it | ignored/unsupported | column policy remains unchanged |
| Revoked membership | canonical membership suppresses legacy fallback; no access | no access | active-membership policy required |
| Deleted event | `404`/no current event; no mutation | `404` | FK/RLS behavior unchanged |

## Confirmed vulnerabilities removed

1. Share-token creation checked a historical `editor` role that is not part of the canonical owner/partner model and did not bind `event_id` and `public_id` to one authoritative event.
2. Gift-list persistence resolved the first row by legacy `events.user_id` and constrained mutations by caller `user_id`, rather than binding every resource to the selected accessible event.
3. Event settings and ceremony handlers duplicated authentication inline and returned raw database error messages.
4. Share creation accepted caller-supplied tokens and unbounded expiry values; custom tokens are now disabled and expiry is restricted to 1–30 days.

## Data and schema preservation

No migration is required for this milestone. No Production DML, migration, grant change, cleanup, backfill or reassignment is performed. The 24-event/11-absent-Auth-owner figures were this milestone's historical snapshot. The later reconciliation records 25 current events (11 absent-Auth-owner exceptions and 14 resolving owners) and replaces fixed numbers with an immediate pre/post-migration count-and-checksum comparison. All memberships, invitations, Budget, expenses, reminders, Timeline, favourites and catalogues remain protected.
